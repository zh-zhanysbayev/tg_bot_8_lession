# Telegram-бот на OpenRouter (Nemotron / Gemma)

Telegram-бот для общения с бесплатными моделями через [OpenRouter](https://openrouter.ai).
Написан на Node.js без внешних зависимостей (нужен Node.js 20.6+).

## Возможности

- Текстовый чат с запоминанием последних 12 сообщений в каждом чате.
- Анализ фотографий: бот скачивает фото из Telegram, кодирует в base64 и отправляет vision-модели. Подпись к фото используется как вопрос.
- Команды: `/start`, `/reset` (сброс контекста).
- Автоматическое переключение между моделями при сбоях (см. ниже).
- Подробные логи: полный текст ошибок OpenRouter и имя модели, давшей итоговый ответ.

## Быстрый старт

1. Создайте бота у [@BotFather](https://t.me/BotFather) и получите токен.
2. Получите ключ на [openrouter.ai/keys](https://openrouter.ai/keys).
3. Создайте файл `.env` по образцу `.env.example`:

   ```env
   OPENROUTER_API_KEY=sk-or-v1-...
   TELEGRAM_BOT_TOKEN=123456789:AA...
   ```

4. Запустите:

   ```bash
   npm start
   ```

`.env` внесён в `.gitignore` — не коммитьте ключи.

## Настройки (необязательные, в `.env`)

| Переменная | По умолчанию | Назначение |
|---|---|---|
| `MODELS` | `nvidia/nemotron-3-ultra-550b-a55b:free,nvidia/nemotron-3.5-lightning:free` | Цепочка моделей для текста |
| `VISION_MODELS` | `google/gemma-4-31b-it:free,nvidia/nemotron-3.5-super-vl:free` | Цепочка моделей для фото |
| `SYSTEM_PROMPT` | дружелюбный помощник | Системный промпт |

Модели указываются через запятую. Первая — основная, остальные — запасные.
Бесплатные модели на OpenRouter периодически появляются и исчезают, актуальный список:
[openrouter.ai/collections/free-models](https://openrouter.ai/collections/free-models).

## Архитектура Fallback

Бесплатные модели нестабильны: упираются в лимиты (HTTP 429), отвечают с ошибками
или возвращают `200 OK` с пустым `content` (reasoning-модель тратит весь лимит токенов
на «рассуждения» и не успевает написать ответ). Чтобы бот оставался отказоустойчивым,
перебор моделей реализован в самом коде (`askModel` в `bot.js`), а не через серверный
параметр `models` OpenRouter — он срабатывает только на ошибках API и не ловит пустые ответы.

Как это работает:

1. Запрос отправляется первой модели цепочки (одна модель — один запрос).
2. Если модель отказала, бот пробует следующую. Отказом считается:
   - HTTP-ошибка (в том числе 429 «rate limit», 404, 5xx);
   - сетевая ошибка или таймаут (120 секунд);
   - пустой ответ: `content` пуст, даже если статус `200 OK` (в том числе `finish_reason: length`).
3. Первый непустой ответ возвращается пользователю. В логе отмечается, какая модель его дала:
   `✔ Финальный ответ дала модель: ... (попытка N из M)`.
4. Если отказали все модели цепочки, пользователь получает понятное сообщение
   (для фото — «Не удалось распознать изображение…»).

Цепочки независимы: для текста и для фото используются разные списки моделей
(`MODELS` и `VISION_MODELS`), потому что не каждая модель принимает изображения
(например, `nemotron-3-ultra` картинки не поддерживает и отвечает 404).

Картинки не хранятся в истории диалога (только пометка `[Фото] …`), чтобы base64
не раздувал последующие запросы.

## Известные ограничения (Known Limitations)

Бесплатные модели (Nemotron, Gemma) хорошо справляются с описанием обычных фотографий,
но не предназначены для сложного OCR. При отправке изображений со стилизованным слитным
текстом они выдают галлюцинации (неверные буквы). Для точного распознавания текста
требуется подключение специализированных OCR-движков (например, Tesseract) или платных
API (Google Vision).

Дополнительно:

- **Ограничения OCR:** бесплатные Vision-модели (Nemotron, Gemma) хорошо описывают обычные фото, но не предназначены для точного распознавания текста (OCR). При отправке изображений со стилизованным слитным текстом (лигатурами) модели выдают галлюцинации. Для решения этой задачи требуется интеграция специализированных OCR-движков (Tesseract) или платных API (Google Vision).
- Бесплатные модели имеют лимиты запросов (в том числе общие у провайдера), поэтому
  Gemma нередко отвечает 429 и запрос уходит на запасную модель.
- Обрабатываются только обычные фото; изображения, присланные как файл (документ),
  и альбомы целиком не поддерживаются.
- Состояние диалогов хранится в памяти процесса и сбрасывается при перезапуске бота.
